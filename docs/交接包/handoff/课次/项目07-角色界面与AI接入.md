# 角色界面与 AI 接入（系统实现扩展）

> 日期：2026-11-12
> 目标：管理员与普通用户看到不同页面；整体界面升级为科技感暗色；接入“用户自己的 API Key”调用大模型。
> 原则：已有业务（企业/风险/可视化/登录）不重写逻辑，只做界面分层与增量功能。

## 一、角色与页面矩阵

| 页面 / 能力 | 管理员 | 普通用户 | 实现方式 |
| --- | --- | --- | --- |
| 概览（驾驶舱 / 工作台） | 管理驾驶舱：账号数、管理员数 | 我的工作台：AI 就绪状态 | 同一视图，模板按角色分支 |
| 企业库、风险库、可视化 | ✅ | ✅ | 原有视图 |

## 二、细分模块与功能

### 1. 工作台（角色分流）

- **管理员驾驶舱**：企业总数、风险记录、高风险数、系统账号数（含管理员人数）；风险 Top5；快捷入口；AI 解读入口。
- **普通用户工作台**：企业/风险/高风险三项业务指标 + “AI 解读（已就绪/未配置）”卡片；Top5；快捷入口。
- 顶部角色徽标：管理员金色、普通用户青色；侧栏“管理”分组仅管理员可见。

### 2. 企业模块

- 列表：关键词、经营状态、类别筛选，分页保留条件；空状态。
- 详情：基础信息 + 最新风险 + 关联风险表。
- 深色主题下表格、徽标、按钮统一换肤。

### 3. 风险模块

- 列表：名称/等级筛选、四维得分列、分页。
- 详情：百分制总分、四维得分、12 项原始指标、**AI 解读面板**。
- 分数已按百分制（0–100）展示。

### 4. 可视化模块

- 企业：状态饼图、注册资本区间、成立年份。
- 风险：等级饼图、得分分布、Top10 表。
- 图表仍是服务端 SVG，可单独下载；页面改为暗色玻璃卡片承托白底图。

### 5. AI 接入模块（本次新增）

| 功能 | 说明 |
| --- | --- |
| 平台选择 | DeepSeek / OpenAI / 自定义（OpenAI 兼容） |
| 接口地址 + 模型名 | 选平台自动带默认值，可改 |
| 我的 API Key | 每账号一条记录；表单留空表示不修改；展示只显示前 6 位 |
| 测试连接 | `GET /models`，不消耗生成额度，返回可用模型名 |
| AI 风险解读 | 风险详情页按钮 → `POST /chat/completions` → 三点式解读 |
| 审计 | 每次成功解读写一条 `audit_log`（动作、对象、IP） |
| 未配置引导 | 无 Key 时返回 `need_key`，前端提示并给配置链接 |

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/settings/ai/` | 配置页与保存 |
| POST | `/api/ai/test/` | 测试 Key，返回 JSON |
| POST | `/api/ai/analyze/` | 传 `risk_id`，返回解读文本 |

### 6. 账号管理模块

- `/manage/users/`：用户名、角色、部门、最近登录、AI Key 状态、启用状态。
- 仅超级用户可进；普通用户 302 到登录页。
- 账号增删改仍交给 Django 后台，避免重复造轮子。

## 七、可实现的边界与风险

1. **Key 存储**：当前明文存库（课程演示），正式环境应加密（如 Fernet）或只存会话；页面不回显完整 Key。
2. **跨域/代理**：调用走标准库 urllib；本机地址绕过系统代理，外部地址沿用系统代理。
3. **模型差异**：只支持 OpenAI 风格 `/chat/completions`，非兼容平台需要适配器。
4. **费用**：测试接口只查 `/models`，解读才消耗 token；演示建议用临时 Key。
5. **权限**：管理员判定为 `is_superuser` 或 `profile.role='admin'`；数据级权限仍待项目 13。

**不能当作真实趋势**，报告中必须注明。

## 十二、评分拆解、预警订阅、对比分享（2026-11-13）

### 评分系统体检结论

| 检查 | 结果 |
| --- | --- |
| 原始指标范围 | 最大 25.00，符合“每项 0–25”的公式假设 |
| 总分上限 | 最大 88.67，无 >100 |
| 四维均值 vs 总分 | 0 条偏差 >0.02，最大偏差 0.005（仅四舍五入） |
| 等级与阈值 | 0 条不一致（<60 低 / 60–80 中 / ≥80 高） |
| 维度上限 | 无 >100 |

公式：`总分 = Σ12项 ÷ 3`，`维度 = Σ3项 × 4/3`，两者数学上等价（总分 = 四维均值）。
未发现计算错误；唯一“隐患”是四舍五入带来的 0.005 级误差，已在测试中留 0.02 容差。
