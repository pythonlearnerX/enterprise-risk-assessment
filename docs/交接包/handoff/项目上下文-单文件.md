## 一、这是什么

一套「企业风险查询 + 评分 + 可视化 + 报告导出」的 Django Web 系统，覆盖课程实训的 6 个模块：

| 模块 | 能力 | 对应课次 |
| --- | --- | --- |
| 企业数据管理 | 列表、8 条件组合查询、分页、详情、CSV 导出 | 项目 04 / 07 / 08 |
| 数据可视化 | 企业 6 图 + 风险 3 图 + 图表 JSON 接口 | 项目 10 / 11 |
| 风险计算与报告 | 12 项指标 → 四维 → 总分 → 等级；A4 PDF 报告 | 项目 12 |
| 用户权限管理 | 登录、会话、角色分流、自定义后台、审计日志 | 项目 06 / 09 / 13 |
| AI 风险预估 | 用户自带 Key 调大模型，**只解释、不参与打分** | 项目 14 |
| 模型部署展示 | Flask + jieba 微服务，Docker 容器化 | 项目 15 |

此外还有三类**加分项**（分析看板 8 视角、重庆区县地图、A/B 实验、AI 解读闭环），
与系统测试报告、答辩 PPT 一起放在 `课次/`。

## 二、5 分钟跑通（照抄即可）

### 0. 前置

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Python | 3.12（3.10+ 均可） | 建议建虚拟环境 |
| MySQL | 8.0 / 8.4 | 本项目开发时用便携版，端口 **3307**；你自己的 MySQL 默认 3306 也行 |

### 1. 装依赖

```bash
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 2. 配置数据库连接（**不要改代码**）

```bash
copy .env.example .env            # macOS/Linux: cp .env.example .env
# 编辑 .env，填你自己的数据库账号密码与端口
```

`risk_project/settings.py` 会自动读取根目录 `.env`（零依赖实现，见文件顶部 `_load_dotenv`）。
`.env` 已在 `.gitignore` 里，不会被提交。

### 3. 建库 + 建表

```sql
CREATE DATABASE risk_assessment DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

```bash
python manage.py migrate
python manage.py createsuperuser
```

### 4. 导入数据

```bash
python data_import.py
```

只导 100 行样本快速验证：

```bash
python data_import.py --sample
```

### 5. 起服务

```bash
python manage.py runserver 127.0.0.1:8021
```

### 6. 验收（这三条都能过，说明环境没问题）

```bash
curl http://127.0.0.1:8021/health/          # 期望 {"ok": true, "mysql": "8.4.x", "tables": [...]}
python manage.py test risk_app              # 期望 Ran 80 tests ... OK
python manage.py check                      # 期望 System check identified no issues
```

> `/health/` 不用登录，是专门给排错用的：能返回数据库版本和表名列表，说明 Django ↔ MySQL 通了。

## 六、已知限制（写报告要如实交代）

1. **数据只有一期快照**：`风险详情` 页的「近年评分」是 `seed_demo_history` 生成的**模拟值**（0.90/0.95/1.00 等比缩放），页面有徽标、图下有说明，不参与任何统计与结论；
2. **企业类型码未映射**：`firm_type` 存的是源数据代码（1100/1151…），课程未给字典；
3. **AI Key 明文入库**：课程环境可接受，生产需加密或接 KMS；
4. **PDF 用 fpdf2 手绘**：不依赖 Office/浏览器，但版式是固定模板，不是 HTML 渲染；
5. **开发服务器并发有限**：50 并发错误率约 18–22%（`runserver` 监听队列饱和），生产需换 gunicorn/waitress；
6. **四维高度共线**（α=0.988）：不可当成四个独立风险源解读，报告「方法局限」已写明。

## 1. 硬性规则（违反会导致返工）

1. **不要改 `risk_calc.py` 的评分公式与 60/80 阈值**，除非用户明确要求。分数是报告与答辩的核心，改公式会让所有既有结论（基尼、卡方、看板数字）失效。
2. **不要在视图里写裸 SQL**：本项目统一走 ORM；只有 `/health/` 与 EXPLAIN 类诊断才用 `connection.cursor()`。
3. **不要给数据接口加 `@cache_page`**：曾经加过 60 秒缓存，导致「改完分数图表不更新」，排查了很久（见 `docs/RUNBOOK.md` 的坑 2）。
4. **不要用 `request.GET.get("ids")` 取多选参数**：必须 `getlist`（坑 5）。
5. **权限必须拦在后端**：模板里 `{% if %}` 只控制显隐，视图要加 `@login_required` / `@admin_required`。
6. **模拟数据必须标注**：任何造出来的数据都要在字段 `note` 或页面徽标里写明「模拟」，参见 `seed_demo_history.py`。
7. **不要把密码/Key 写进代码**：连接参数走 `.env`（`settings.py` 已实现零依赖加载）。
8. **改完必须跑**：`python manage.py test risk_app`（80 条）+ `python manage.py check`，两条都要绿。

## 5. 这个项目里已经踩过的坑（别重踩）

| # | 坑 | 正确做法 |
| --- | --- | --- |
| 1 | 改分数没改等级，出现「88.67 分 / 中风险」 | `RiskIndicator.save()` 里统一调 `recalculate()` |
| 2 | 图表接口加了 `cache_page(60)`，改数据不刷新 | 数据接口不加页面缓存 |
| 3 | `json_script` 二次编码 → 图表空白 | 视图传 Python 对象，不要先 `json.dumps` |
| 4 | 热力图 `visualMap` 缺 `dimension` → 整片灰 | 显式指定数值所在的维度 |
| 5 | 复选 `?ids=1&ids=2` 用 `get()` 只拿到一个 | `request.GET.getlist("ids")` |
| 6 | 服务端导出 PDF（Edge 无头 / Word COM）失败 | 用 fpdf2 纯 Python 绘制 |
| 7 | 企业详情「经营状态」显示裸码 1/2/3 | 模板里映射成 在营/注销/吊销 |
| 8 | 未登录访问 `/alerts/` 500 | 视图补 `@login_required` |

## 三、五个必须知道的事实（写报告/答辩都会用到）

1. **总分 = 四维均值**（四维各 0–100，总分 0–100，非加权和）；`breakdown` 里乘 0.75 只是展示用的 25 分制换算；
2. **四维高度共线**：平均 r̄=0.9524、Cronbach α=0.9877、PC1 解释 96.43%，且 **PC1 权重 = 25.0/25.1/25.0/24.9 ≈ 等权**——所以「等权是拍脑袋」这个质疑在数据上不成立；
3. **但单维不能替代四维**：单维 Top10% 名单与四维只重合 59.6%–61.9%，等级改判 11.4%–13.8%——四维合并是降噪；
4. **经营状态与风险等级无关**：χ²=1.72、df=4、p=0.787，所以系统没有「注销企业自动预警」这类规则；
5. **近年评分是模拟数据**：`seed_demo_history` 按 0.90/0.95/1.00 等比缩放，仅演示趋势组件，页面有徽标。

## 四、评分链路（最重要的一段）

```python
# risk_app/risk_calc.py
calc_risk(values, mode="count"|"points", year_weights=..., dim_weights={...0.25})
  ├── 每维 3 年指标 → 加权平均
  ├── mode="count" ：安全分 = 25 − 平均次数，风险分 = 25 − 安全分（扣分制）
  ├── mode="points"：输入本身是 0–25 风险点，直接取均值
  ├── 四维 → 总分为四维均值（0–100）
  └── risk_level(total)：≥80 高 / ≥60 中 / 其余低
```

**不要改公式与阈值**，除非用户明确要求：基尼、卡方、看板文案都基于这套分数。

## 三、八个「曾经踩过、别重踩」的坑

1. **改分数没改等级** → 页面出现「88.67 分 / 中风险」。修法：`RiskIndicator.save()` 里统一 `recalculate()`。
2. **数据接口加了 `@cache_page(60)`** → 改完数据图表一分钟才变。修法：数据接口不加页面缓存。
3. **`json_script` 二次编码** → 图表数字是字符串，图空白。修法：视图传 Python 对象，别先 `json.dumps`。
4. **热力图 `visualMap` 缺 `dimension`** → 整片一色。修法：显式指定数值所在维度。
5. **多值参数用 `get()`** → 勾选 3 家只对比 1 家。修法：`request.GET.getlist("ids")`。
6. **服务端导出 PDF 两条路都失败** → Edge 无头打印报 `Missing headless user data directory`；Word COM 报未注册。修法：fpdf2 纯 Python 绘制。
7. **企业详情经营状态显示裸码 `1`** → 模板没映射。修法：模板里 `{% if ope_status == '1' %}在营{% elif ... %}`。
8. **未登录访问 `/alerts/` 500** → 视图漏了 `@login_required`。修法：补装饰器（这条是测试报告里的 D-08）。

## 二、算法与位置（改之前先看这里）

| 量 | 实现 | 关键细节 |
| --- | --- | --- |
| 分位数 | `analytics._quantile` | 位置 `(n−1)·p`，非整数线性插值（与 numpy 默认口径一致） |
| 基尼 | `build()` 内 | 洛伦兹曲线取 201 点，梯形积分，`G = 1 − A/5000` |
| 前 10% 贡献 | `build()` 内 | 降序取 `n//10` 求和 ÷ 总和 |
| 皮尔逊 r | `analytics._pearson` | 标准积矩相关；n=10000 时临界 r 仅 0.0196，**要看 r 大小别只看 p** |
| Spearman | `analytics._spearman` | 平均秩后算皮尔逊 |
| Cronbach α | `analytics._redundancy` | 标准化公式 `α = k·r̄ / [1 + (k−1)·r̄]`，k=4 |
| PC1 | `analytics._pc1` | 幂迭代 300 次，求相关矩阵最大特征值与载荷；占比 = λ₁/k |
| 卡方 | `build()` 内 + `_chi2_sf` | 3×3 列联表；df=4 有闭式上尾解，不依赖 scipy |
| 标准化残差 | `build()` 内 | `(O−E)/√E`，与卡方同源（Σ残差²=χ²） |
| 组内 z | `build()` 内 | 按资本档算 μ/σ（档内 n≥30 才算），`z=(x−μ)/σ`，取 z≥2 |
| cohort | `build()` 内 | 按成立年份 6 段，算高风险率 |
| 冗余度 | `analytics._redundancy` | 2026-11-24 新增；同时给 Top10% 重合率与等级改判率 |

## 三、答辩时必须讲清的三个「反直觉」

1. **等级不是唯一结论**：因为 60/80 阈值，40–59 段只有 213 家、60–79 段 2266 家（断崖），所以报告同时给「全库百分位」和「同规模均值」，等级会跳档、百分位不会。
2. **四维冗余但合并有益**：α=0.988、PC1=96.4%，四维是一个构念的四个切面；**等权恰好等于 PC1 权重**，所以「等权是拍脑袋」不成立；但单维替代会换掉约 4 成头部名单、改变 11%–14% 企业等级——合并是四次重复测量取平均，属于降噪，不是重复计权。
3. **经营状态与风险无关**：χ²=1.72、p=0.787，12 格残差全在 ±1.1 内。「注销/吊销企业更高危」在本数据里不成立，所以系统没有按状态预警的规则。

### 1. 统一句式模板，每页都是「定义 + ①②③ + 分号」

原句（第 14 页结论条）：

> 四维不是四个独立风险源，是一个构念的四个切面；等权 0.25 恰好等于主成分权重，不存在「权重拍脑袋」的问题；但单维替代不行：Top10% 名单只重合 59.6%–61.9%，等级改判 11.4%–13.8% —— 合并是在降噪；所以：保留等权四维合并……

四句话四个分号，每句都是「判断 + 数据 + 转折」。这是典型的大模型排比节奏，念出来像在读结论摘要，不像在讲自己做的事。

**改法**：一页只留一个判断，其余进讲稿。屏幕上写「等权不是拍脑袋，是算出来的」，嘴上说另外三句。

### 2. 抽象词密度过高

`构念`、`降噪`、`裁决`、`可复算`、`闭环`、`口径`——单个都对，连在一起就像在展示词汇量。
真实汇报里，学生会说「四个维度其实测的是同一个东西」，而不是「四维是同一构念的四个切面」。

### 3. 每一页都有一条「结论条」

19 页里有 11 页带结论条。**这是最明显的 AI 痕迹**：人不会每页都总结，因为总结是讲出来的。
屏幕上结论铺满，等于把讲者要说的都写完了，观众读屏幕、不听人。

### 4. 对仗式标题连用

「阈值法有个断崖」「谁在同规模里不对劲」「四维到底是不是四个维度」——单看不错，连续六页同款结构，节奏完全一样，读起来像模板套出来的。

### 5. 小数位太多

0.9877、96.43%、22.31%、59.6%–61.9%。真实汇报会口语化：**0.99、96%、两成二、六成**。精确值放备注或附录。

### 6. 没有一句「过程」

全篇都是结论，没有「我一开始以为 X，后来发现 Y」。人的汇报一定有这个过程，而且**过程比结论更可信**。现在这份 PPT 无法证明「这些结论是踩坑踩出来的」，只能证明「作者会查资料」。

## 三、两条备选叙事线（给接手 AI 的选项）

### 线 A：跟着一个真实问题走（推荐给非专业评委）

1. 开场：重庆一家餐饮连锁要评估 20 家供应商，人工看 20 份材料要两天；
2. 系统怎么做的：输入企业名 → 看到分数、四维、12 项来源；
3. 中途发现问题：四个维度几乎一样（α=0.99）→ 那我为什么要分四维？
4. 于是加统计看板：验证「分档合理吗、状态有用吗、谁异常」；
5. 结论：分数可用，但**不能当四个独立维度解读**；异常名单比排行榜有用；
6. 收尾：一套能复算、能解释、能交接的系统。

好处：外行跟得上；每个技术点都挂在"我要解决什么"上。
代价：需要 3–4 张"过程页"（问题、尝试、失败、修正），这些页现在的 PPT 一张都没有。

### 线 B：一页一个可验证结论（推荐给严格评委）

每页固定三块：**断言 → 证据（一个数字/一张图）→ 所以系统这么做**。
例如「经营状态和风险无关（χ²=1.72，p=0.787）→ 所以没做按状态预警」。
好处：被追问时最稳，每页都能独立成立。
代价：像审计报告，开场需要一句人话把气氛拉回来。

### 不推荐：技术链路线（路由→视图→模型→模板）

老师明确说会问「Django 实现链路」，但**这类内容适合被问，不适合主动讲**。主动讲会失去非专业听众。

## 四、更基础的问题：不懂专业的用户能看懂这个平台吗

**诚实结论：现在不能。** 逐项看：

| 页面元素 | 专业人员看到 | 非专业用户看到 | 问题 |
| --- | --- | --- | --- |
| 首页 `10000 / 10000 / 234` | 数据规模与高危占比 | 三个数字，不知道好坏 | 缺「234 意味着什么」 |
| 详情页 `88.67` 旁边 `92 / 89.32 / 97.32 / 76` | 四维得分，合规最差 | 四个不知道含义的数 | 缺一句「哪个维度拉高了分」 |
| `全库百分位 100.0%` | 高于全库所有企业 | 100% 是不是满分？ | 术语歧义 |
| `同规模差值 +53.93` | 比同资本档均值高 54 分 | 差值是跟谁比？ | 缺对比对象 |
| 列表页筛选项「企业类型 1100」 | 源数据代码 | 完全不懂 | 代码未映射 |
| 「合规风险 / 风险点 / 扣分制」 | 清楚 | 不懂 | 无术语解释 |
| 分析看板「基尼系数 0.394」 | 分布集中度 | 不认识 | 有「读法」但仍是术语 |

### 七条改进（按性价比排序）

1. **每个分数旁边加一句白话**：把「88.67」改成「88.67 · 高于全库 99% 的企业，建议人工核查」——数据已有（百分位），只差一句模板；
2. **等级徽标带行动建议**：高风险 → 「建议 7 日内核查」，中风险 → 「纳入季度抽查」，低风险 → 「常规监测」；
3. **术语悬浮解释**：合规风险、风险点、扣分制、百分位，鼠标悬停给一句 20 字解释（前端一个 `title` 或自定义 tooltip 即可）；
4. **首页按角色给结论**：普通用户不该看到「10000/10000/234」，应该看到「最近 7 天需要关注的 5 家企业」；
5. **详情页加「为什么是这个分」**：12 项指标按分数降序排，第一行加粗 + 一句话「主要来自合规类的 3 次处罚」；
6. **企业类型码映射**：至少给常见 5 个代码中文名，其余显示「其他（代码 1100）」；
7. **数据可信度标签**：现在只有「含演示模拟数据」，应扩展为「数据截止 2026-11-06」这类时间标签，用户才知道能不能信。

### 一句话判断

> 这个平台现在是「给会看数据的人用的工具」，还不是「给业务人员用的产品」。
> 差别不在功能，在**翻译层**——把分数翻译成结论、把术语翻译成人话、把报表翻译成建议。
> 这一层不需要新算法，只需要文案 + 几条模板，是性价比最高的改造方向。

## 五、你要自己把关的三件事

1. **数字对得上**：它交稿后，抽 3 个数字去 `docs/STATISTICS.md` 核；对不上就整段退回；
2. **过程是真的**：PPT 里「我一开始以为…」那种页，必须是真实发生过的（比如分档断崖、等级不同步、缓存 60 秒），不要让它编故事；
3. **限制要说**：报告里那六条限制一条都不能少——评委最容易在这里追问，主动写比被问出来强。

## 五、重新生成截图的方法（两步）

1. 抓页面：`_tmp/工具脚本/capture_ppt_pages.py`（双账号登录，取 HTML 并内联 `/static/`）；
2. 补接口数据：`_tmp/工具脚本/inject_offline_fetch.py`（把 `/api/chart/*`、`geo.json` 响应写成 `fetch` 垫片，否则离线渲染图表是空的）；
3. 渲染：用任意无头浏览器按 1600×960 截图；本项目用 DSH 的 `vision_html_screenshot`。
