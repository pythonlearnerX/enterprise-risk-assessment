## 二、算法与位置（改之前先看这里）

| 量 | 实现 | 关键细节 |
| --- | --- | --- |
| 分位数 | `analytics._quantile` | 位置 `(n−1)·p`，非整数线性插值（与 numpy 默认口径一致） |
| 基尼 | `build()` 内 | 洛伦兹曲线取 201 点，梯形积分，`G = 1 − A/5000` |
| 前 10% 贡献 | `build()` 内 | 降序取 `n//10` 求和 ÷ 总和 |
| 皮尔逊 r | `analytics._pearson` | 标准积矩相关；n=10000 时临界 r 仅 0.0196，**要看 r 大小别只看 p** |
| Spearman | `analytics._spearman` | 平均秩后算皮尔逊 |
| Cronbach α | `analytics._redundancy` | 标准化公式 `α = k·r̄ / [1 + (k−1)·r̄]`，k=4 |
| PC1 | `analytics._pc1` | 幂迭代 300 次，求相关矩阵最大特征值与载荷；占比 = λ₁/k |
| 卡方 | `build()` 内 + `_chi2_sf` | 3×3 列联表；df=4 有闭式上尾解，不依赖 scipy |
| 标准化残差 | `build()` 内 | `(O−E)/√E`，与卡方同源（Σ残差²=χ²） |
| 组内 z | `build()` 内 | 按资本档算 μ/σ（档内 n≥30 才算），`z=(x−μ)/σ`，取 z≥2 |
| cohort | `build()` 内 | 按成立年份 6 段，算高风险率 |
| 冗余度 | `analytics._redundancy` | 2026-11-24 新增；同时给 Top10% 重合率与等级改判率 |

## 三、答辩时必须讲清的三个「反直觉」

1. **等级不是唯一结论**：因为 60/80 阈值，40–59 段只有 213 家、60–79 段 2266 家（断崖），所以报告同时给「全库百分位」和「同规模均值」，等级会跳档、百分位不会。
2. **四维冗余但合并有益**：α=0.988、PC1=96.4%，四维是一个构念的四个切面；**等权恰好等于 PC1 权重**，所以「等权是拍脑袋」不成立；但单维替代会换掉约 4 成头部名单、改变 11%–14% 企业等级——合并是四次重复测量取平均，属于降噪，不是重复计权。
3. **经营状态与风险无关**：χ²=1.72、p=0.787，12 格残差全在 ±1.1 内。「注销/吊销企业更高危」在本数据里不成立，所以系统没有按状态预警的规则。

## 五、被问到时的一句话（背这五句）

1. 「基尼 0.394：风险中等偏集中，不是平均摊开，也不是几家独占。」
2. 「PC1 权重 25.0/25.1/25.0/24.9，跟等权差 0.2 个点——等权不是拍脑袋，就是主成分解。」
3. 「单维替代会让 Top10% 名单只重合六成、11%–14% 企业等级改判，所以四维合并在降噪。」
4. 「卡方 1.72 远小于临界 9.49，p=0.787，状态与等级无关，所以我们没做按状态预警。」
5. 「近年评分是模拟的，只为演示趋势组件，带标记、有徽标，不参与任何结论。」
