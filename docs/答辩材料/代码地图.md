## 一、请求链路（图2 必考点，对应真实文件）

一次 `GET /enterprise/list/` 在项目里的完整路径：

| 步骤 | 发生在 | 文件与位置 |
| --- | --- | --- |
| ① 浏览器发起 HTTP 请求 | 浏览器 | `GET /enterprise/list/?status=1` |
| ② 根路由分发 | `risk_project/urls.py` 第 6 行 | `path("", include("risk_app.urls"))` |
| ③ 子路由匹配 URL | `risk_app/urls.py` 第 19 行 | `path("enterprise/list/", views.enterprise_list, name="enterprise_list")` |
| ④ 调用视图函数 | `risk_app/views.py` 第 212 行 | `def enterprise_list(request)` |
| ⑤ 视图里做权限判断 | `views.py` 第 211 行 | `@login_required`（未登录跳 `/login/?next=…`） |
| ⑥ ORM 读写 MySQL | `views.py` 第 219–260 行 | `Enterprise.objects.filter(...)`，最终生成 SQL |
| ⑦ 渲染模板 | `views.py` 第 300 行附近 | `render(request, "enterprise_list.html", {...})` |
| ⑧ 模板继承与渲染 | `risk_app/templates/enterprise_list.html` | `{% extends "base.html" %}`，`{% for ent in page_obj %}` |
| ⑨ 返回 HTML 给浏览器 | Django `HttpResponse` | 状态码 200，浏览器解析 CSS/JS 后出图 |

> 老师若追问“中间件在哪”：`risk_project/settings.py` 的 `MIDDLEWARE`，`SessionMiddleware` 负责 session、`CsrfViewMiddleware` 负责 CSRF、`AuthenticationMiddleware` 把 user 挂到 request 上（所以模板能直接用 `user`）。

1. 用 admin 登录 → 侧栏出现「管理」组（管理后台 / 用户管理 / AI 解读记录 / 数据后台）；
