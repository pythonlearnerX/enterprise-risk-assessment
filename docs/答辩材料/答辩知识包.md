## 3. 一次请求的链路（必考，9 步）

以 `GET /enterprise/list/` 为例：

1. 浏览器发起 HTTP 请求；
2. `risk_project/urls.py` 根路由 `path("", include("risk_app.urls"))` 分发；
3. `risk_app/urls.py` 的 `path("enterprise/list/", views.enterprise_list)` 匹配；
4. 调用 `views.enterprise_list()`，函数上 `@login_required` 先判断登录；
5. 视图从 `request.GET` 取筛选参数，逐个 `filter()` 叠加；
6. ORM 生成 SQL 查 MySQL，`Paginator` 只取当前页（LIMIT/OFFSET）；
7. `render(request, "enterprise_list.html", context)`；
8. 模板 `{% extends "base.html" %}` + `{% for %}` 渲染表格，`{% static %}` 引资源；
9. 返回 `HttpResponse`（200 + HTML），浏览器渲染。

追问：
- 中间件：`settings.py` 的 `MIDDLEWARE`，Session / CSRF / Authentication 三个最相关；
- `name=` 的作用：模板 `{% url 'risk_app:enterprise_list' %}` 反向解析，改路径不用改模板；
- 为什么用 ORM：防注入、筛选可组合、换库不改代码。

## 4. 数据与评分（回答“分数怎么来的”）

- 12 项指标：`cai_1..3`（财务/近 1-3 年被裁判）、`s_an_1..3`（经营/立案）、`li_an_1..3`（合规/被立案）、`zhi_1..3`（质量/被执行）。
- 四维各 25 分，合计 100；等级 `<60 低 / 60–80 中 / ≥80 高`。
- 评分函数 `risk_calc.calc_risk()`，两种口径，**都是风险分越大越危险**：
  - `count`（事件次数，扣分制）：安全分 = `max(0, 25 − 平均次数×1)`；**风险分 = 25 − 安全分**，即“被扣掉的分”；总分 = Σ 风险分×权重×4；
  - `points`（当前数据集）：维度风险分 = 三项平均风险点，总分 = 四维之和。
- 关键理解：扣分制扣的是“安全分”，扣掉多少就是风险多少；
  0 次 → 0 分（低风险），3 次/维 → 12 分，30 次/维 → 100 分（高风险）。
- 当前数据是 **points 口径**，因为 CSV 的 12 列本身就是 0–25 的风险点，越大越危险；扣分制留给真实“次数”数据。
- 改分数后等级自动重算：`RiskIndicator.save()` 调 `recalculate()`；图表接口无缓存，刷新即变。
- 实测：总分最高 88.67，无超 100；四维均值与总分最大偏差 0.005（四舍五入）。

## 9. 预设问答（老师问到时直接用）

1. **几张表？** 9 张：企业、风险、角色、审计、AI 配置、快照、预警、A/B 相关、AI 记录。

6. **权限是前端藏还是后端拦？** 两端都做，模板不渲染 + 视图装饰器拦截。
7. **403 怎么触发？** 装饰器 `raise PermissionDenied`，Django 渲染 `403.html`。
8. **真分页吗？** 是，Paginator 只查当前页。
9. **图表数据怎么来？** 三个 JSON 接口 + 首屏内联，断网也能显示。
10. **断网能用吗？** 能，Bootstrap/ECharts/地图都在本地。
