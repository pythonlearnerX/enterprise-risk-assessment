二、实训内容
（一）实训载体：企业风险评估系统
本次实训以“企业风险评估系统”为项目载体。该系统面向银行信贷、供应链金融、投资尽调等场景，为业务人员在放款或合作前提供企业风险核查能力。典型业务流程为：输入企业名称或统一社会信用代码 → 调取企业工商注册信息 → 调取司法与经营风险指标 → 按模型计算风险得分与风险等级 → 自动生成风险分析报告 → 借助大模型与本地 NLP 模型给出风险预估与文本风险识别结论。
系统采用 B/S 架构与 Django 的 MTV 设计模式，后端使用 Python + Django + ORM 完成业务逻辑与数据访问，数据库使用 MySQL 8.0，前端使用 HTML + Bootstrap + ECharts 完成页面渲染与可视化，AI 部分包含“调用大模型平台”与“Docker 部署本地轻量化 NLP 模型”两条技术路线。
系统共划分六个核心业务模块，如表 1-1 所示。本次实训涉及的环境安装与数据集梳理是全流程的起点，为后续各模块开发提供环境与数据基础。

（三）关键步骤
步骤 1：安装 Python 并创建虚拟环境
从 Python 官网下载 3.10 及以上版本的 64 位安装包，安装时务必勾选 “Add Python to PATH”。安装完成后打开命令行，依次执行以下命令完成验证与虚拟环境创建。
python --version                 # 预期输出 Python 3.10.x 及以上
where python                      # 确认解释器路径指向预期安装目录
cd /d D:\risk_project             # 进入项目根目录（自定义）
python -m venv venv               # 创建虚拟环境，生成 venv 目录
venv\Scripts\activate             # 激活虚拟环境，命令行前缀出现 (venv)
python -m pip install --upgrade pip
pip --version                     # 确认 pip 已指向 venv 内的版本
说明：创建虚拟环境时若不写路径，默认在当前目录生成 venv 文件夹；激活成功后命令行前缀显示 (venv)。若 PowerShell 提示“禁止运行脚本”，需先执行 set-ExecutionPolicy -Scope CurrentUser RemoteSigned，或改用 cmd 命令行操作。
步骤 2：安装与初始化 MySQL 8.0
下载 MySQL 8.0 安装包，选择 “Server only” 或 “Developer Default” 安装类型；在配置阶段设置 root 密码、选择 “MySQL as a Service” 以便开机自启，字符集选择 utf8mb4。安装完成后验证服务状态与登录。
net start mysql                   # 启动 MySQL 服务（服务名以安装时为准）
mysql -u root -p                  # 输入 root 密码进入 MySQL 控制台
SELECT VERSION();                 # 预期输出 8.0.x
SHOW DATABASES;                   # 查看已有数据库
EXIT;
常见问题：若 net start mysql 提示服务名无效，在“服务”管理器中查找实际服务名（如 MySQL80）；若忘记 root 密码，可通过跳过权限校验的方式重置，安装时建议将密码记录在实验报告中。
步骤 3：创建数据库与专用账号
为符合最小权限原则，禁止业务代码使用 root 直接连接数据库。执行以下 SQL 创建数据库与专用账号，该账号与密码将写入 Django 的 settings.py。
CREATE DATABASE risk_assessment
DEFAULT CHARACTER SET utf8mb4
COLLATE utf8mb4_general_ci;
CREATE USER 'risk_user'@'localhost' IDENTIFIED BY 'risk123456';
GRANT ALL PRIVILEGES ON risk_assessment.* TO 'risk_user'@'localhost';
FLUSH PRIVILEGES;
SHOW GRANTS FOR 'risk_user'@'localhost';   -- 验证授权结果
步骤 4：安装 IDE 与项目依赖
安装 PyCharm 社区版或 VS Code，将项目解释器指定为步骤 1 创建的 venv\Scripts\python.exe。随后在已激活虚拟环境的终端中安装本项目所需依赖，并导出依赖清单便于环境重建。

步骤 7：运行脚本并解读结果
在 PyCharm 中运行 dataset_process.py（或在已激活虚拟环境的终端执行 python dataset_process.py），观察并记录以下输出：数据规模是否为 10000 条、关键字段是否存在缺失、企业类别的 E/P 分布、经营状态的 1/2/3 分布、四类风险指标的非零占比。
结果解读要点：
（1）企业类别中 E（企业）与 P（个体户）的比例决定了后续列表页筛选下拉的取值设计。
（2）经营状态以 1（在营）为主、存在部分 2（注销）与 3（吊销），说明系统必须对非在营企业做醒目标识。
（3）多数企业的 12 项风险指标为 0，说明“无司法记录”的企业占多数，风险评分算法必须以“扣分制”而非“加分制”设计，否则会把低风险企业误判为高风险。
（4）注册资本、成立日期等字段存在空值，导入数据库时必须做类型转换与空值兜底，这一结论直接指导项目 4 的数据导入脚本设计。

MTV 模式 | Django 的模型（Model）—模板（Template）—视图（View）分层架构，职责分离 | 项目4定义 Model，项目5~12编写 View 与 Template
ORM | 对象关系映射，用 Python 类映射数据库表，用类方法与查询集替代手写 SQL | Enterprise、RiskIndicator 模型类对应 enterprise、risk_indicator 两张表
虚拟环境 | 独立的 Python 运行环境（venv），隔离项目依赖，避免版本冲突 | 项目根目录下创建 venv，所有依赖只装入该环境
宽表 | 字段数量多、以单表承载多维度属性的数据表结构 | 企业表 59 列、风险表 19 列，均为典型宽表
DataFrame | pandas 的二维表数据结构，支持按列选取、类型转换、分组统计 | 数据集梳理脚本以 DataFrame 读取 CSV 并统计

--- TABLE 8 ---
现象 | 原因 | 处理办法
python 不是内部或外部命令 | 未勾选 Add Python to PATH | 重新安装并勾选该选项，或手工将安装目录与 Scripts 目录加入系统 PATH
venv\Scripts\activate 无法执行 | PowerShell 执行策略限制 | 执行 set-ExecutionPolicy -Scope CurrentUser RemoteSigned，或改用 cmd
pip 安装超时 | 默认源访问缓慢 | 使用国内镜像：pip install -i https://pypi.tuna.tsinghua.edu.cn/simple 包名
MySQL 服务名无效 | 服务名与命令不一致 | 在“服务”中查看实际名称，如 MySQL80，再执行 net start MySQL80
CSV 读取中文乱码 | 文件编码非 UTF-8 | 读取时指定 encoding='gbk'，或将文件另存为 UTF-8 编码
读取时报 dtype 警告 | 未指定数据类型，编号列被推断为数值 | 读取时统一加 dtype=str，需要数值时再用 pd.to_numeric 转换
脚本提示文件不存在 | 工作目录与数据目录不一致 | 使用 os.path.dirname(os.path.abspath(__file__)) 定位脚本所在目录，用相对路径拼接
