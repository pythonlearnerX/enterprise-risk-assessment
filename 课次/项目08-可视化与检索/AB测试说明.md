# A/B 测试说明与改动收益（2026-11-17）

> 面向：课程答辩、后续接手同学。
> 目标：用对比试验回答“这次改动到底有没有用”，而不是凭感觉说“更好看了”。

---

## 一、A/B 测试六步法在本项目中的落地

| 步骤 | 做法 | 对应代码/页面 |
| --- | --- | --- |
| 1 提出假设 | 每个实验写清“改什么 → 影响哪个行为 → 期望方向” | `ABExperiment.hypothesis` |
| 2 选定指标 | 一个主指标，服务端可采集，分子分母都明确 | `metric` / `metric_label` |
| 3 随机分组 | `md5(实验标识+用户ID)` 取模，同用户固定同组 | `risk_app/abtest.py: bucket()` |
| 4 上线采集 | 曝光去重（同用户同日一次）+ 转化事件 | `_ab_impression` / `_ab_convert` |
| 5 统计判断 | 两比例 z 检验 + 95% CI + 样本量 | `proportion_test` / `decide` |
| 6 决策落地 | 上线 B / 保留 A / 继续采集，结论可写回实验 | `/ab/` 页面 + `ab_toggle` |

### 为什么这样分组

- **确定性哈希**：同一用户永远同组，刷新不换组，避免“同一个人既算 A 又算 B”污染结果；
- **加实验标识**：不同实验相互独立，不会出现“总是同一批人当实验组”；
- **曝光去重**：一人一天只算一次曝光，防止反复刷新把分母灌大。

### 统计口径

```
A 转化率 p₁ = a_conv / a_imp      B 转化率 p₂ = b_conv / b_imp
合并比例 p̄ = (a_conv + b_conv) / (a_imp + b_imp)
z = (p₂ − p₁) / sqrt(p̄(1−p̄)(1/n₁ + 1/n₂))
p 值 = 2(1 − Φ(|z|))            α = 0.05
95% CI = (p₂ − p₁) ± 1.96·sqrt(p₁(1−p₁)/n₁ + p₂(1−p₂)/n₂)
每组样本量 n = (1.96·sqrt(2p̄(1−p̄)) + 0.84·sqrt(p₁(1−p₁)+p₂(1−p₂)))² / (p₂−p₁)²
```

决策规则：

- p < 0.05 且 B > A → **上线 B**
- p < 0.05 且 B < A → **保留 A**
- p ≥ 0.05 或样本不足 → **继续采集**

## 二、两个实验与结果

### 实验 1：风险行情页顶部快捷导出条

| 项 | 内容 |
| --- | --- |
| 假设 | 导出入口不够显眼，用户在筛选表单里找不到；把“导出当前筛选结果”提到顶部，能提升导出率 |
| 主指标 | 导出率 = 导出次数 / 页面曝光 |
| A 组 | 导出按钮在筛选表单右下（现状） |
| B 组 | 顶部新增快捷导出条（含条数与说明） |
| 流量 | 各 50% |

结果（3000 / 3006 曝光）：

| 组 | 曝光 | 转化 | 转化率 |
| --- | --- | --- | --- |
| A | 3004 | 640 | 21.30% |
| B | 3001 | 798 | 26.59% |

- 差值 **+5.29pp**，相对提升 **+24.8%**
- z = 4.799，**p < 0.0001**，95% CI [3.1pp, 7.4pp]（不含 0）
- 结论：**上线 B**（导出率提升约四分之一，方向与幅度都可信）

### 实验 2：企业列表每页 10 条 vs 20 条

| 项 | 内容 |
| --- | --- |
| 假设 | 每页 20 条减少翻页，用户更快找到目标企业，提升进入详情页的比例 |
| 主指标 | 详情点击率 = 进入企业详情次数 / 列表曝光 |
| A 组 | 每页 10 条 |
| B 组 | 每页 20 条 |

结果（各 3001 曝光）：

| 组 | 曝光 | 转化 | 转化率 |
| --- | --- | --- | --- |
| A | 3001 | 534 | 17.79% |
| B | 3001 | 531 | 17.69% |

- 差值 **−0.10pp**，z = −0.101，**p = 0.919**，95% CI [−2.0pp, +1.8pp]（跨 0）
- 设计所需样本 **6039/组**，当前仅 3001/组
- 结论：**继续采集**（更保守的说法：没有证据表明 B 更好，暂不上线）

> 这个“没效果”的实验同样有价值：它证明系统不是“只要改了就一定涨”，
> 也说明样本量不足时不能下结论——这正是 A/B 测试要防的坑。

### 数据来源声明

截图中的数据来自 `python manage.py ab_simulate`（标记 `source=sim`，页面显示“含模拟数据”）。
课程环境没有真实流量，先用模拟数据把统计链路跑通；真实上线后，同一套代码会累积 `source=real` 的事件。
真实数据（admin/zhangsan 的访问）也在同步记录，只是样本远不足以检验。

## 五、局限与下一步

1. **样本量**：课程环境没有真实流量，结论基于模拟数据，只能证明“方法与链路可用”；
2. **单一指标**：目前只看转化率，缺少“人均导出次数”“7 日留存”等长期指标；
3. **多重比较**：同时跑多个实验时未做 Bonferroni/FDR 校正，正式使用需要；
4. **SRM 检查**：应加“分流比例是否偏离 50/50”的卡方检验，防止分组 bug；
5. **不可用场景**：样本极少或效果极小时，A/B 不如直接看用户访谈；
6. **指标护栏**：可加“页面加载时间不能变慢”这类护栏指标，防止为了转化牺牲性能。
