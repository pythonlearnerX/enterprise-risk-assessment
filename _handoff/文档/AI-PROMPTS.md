# 交给其他 AI 的提示词包（AI-PROMPTS）

> 用途：把这份文件连同仓库链接给对方 AI，让它**改 PPT**、**写实训报告**，并在动手前先给你一份评审反馈。
> 三条提示词按顺序用：**先要反馈（省时间）→ 再改 PPT → 最后写报告**。
> 每条都给「可直接复制」的整块文本，`{}` 里的内容按你的情况替换。

---

## 〇、先决条件（30 秒）

对方 AI 必须能读到仓库，三选一：

| 方式 | 做法 | 适合 |
| --- | --- | --- |
| A. 加协作者 | 仓库 Settings → Collaborators → 邀请对方账号 | 对方有自己的 GitHub 账号并在同一工具里登录 |
| B. 临时改公开 | Settings → General → 最下方 Change visibility → Public | 只是给一次建议，之后可改回 Private |
| C. 打包上传 | 把仓库 zip 与本文件一起上传到对方对话 | 对方不支持读仓库 |

> 仓库里 `AGENTS.md` 是给 AI 的入口，`docs/` 下有架构、统计、报告、PPT 复盘的完整说明。
> **务必让它先读 `AGENTS.md` 与 `docs/STATISTICS.md`**，否则它会自己编数字。

## 一、提示词 A：先要「评审反馈」（推荐第一步）

目的：让它在动手前指出问题，避免它按自己的想法重写一遍你不想要的东西。

```text
你是一位有企业信息化项目验收经验的评审，不是执行者。先不要改任何文件。

【背景】
这是一个学生课程实训项目「企业风险评估系统」（Django 6 + MySQL 8.4），
GitHub 仓库：{仓库地址}，请先读：
1) AGENTS.md（项目规约）
2) docs/PPT-REVIEW.md（上一版 PPT 的自评，含我认可的批评）
3) docs/STATISTICS.md（全部统计口径与实测值）
4) 课次/项目17-答辩PPT/README.md（现有 19 页的结构与图表取舍）

【任务】
读完上述文件后，只输出评审意见，不要产出成品。要求：
1. 指出 PPT 结构上最该改的 3 处（按「改了收益最大」排序），每处说明：现在什么问题、改成什么、为什么；
2. 指出报告（实训报告）最容易失分的 2 个地方；
3. 指出 docs/PPT-REVIEW.md 里你认为「过度自我批评」或「判断错了」的 2 条；
4. 给我 1 个「只改 4 页、2 小时内能做完」的最小方案；
5. 最后用一句话回答：如果老师只问一个问题，最可能问什么？

【约束】
- 不要复述文件内容，不要写「综上所述」这类总结；
- 不要提出需要新增数据或新增功能才能实现的建议；
- 不要编造任何数字，引用数字必须注明来自 docs/STATISTICS.md 还是实测报告；
- 输出用中文，控制在 800 字以内，分点写，不要长段落。
```

**为什么先要反馈**：把它当评审而不是执行者，能逼它先暴露判断差异。你看完这 800 字再决定要不要它动手，比它直接改完你又不满意省事。

## 二、提示词 B：改 PPT

```text
你要修改一份课程答辩 PPT。仓库：{仓库地址}

【第一步：必读，不要跳过】
- AGENTS.md
- docs/PPT-REVIEW.md  ← 这份文件列出了「AI 腔」的 6 个具体特征，是本任务的核心要求
- docs/STATISTICS.md  ← 所有数字的唯一来源
- 课次/项目17-答辩PPT/README.md
- 文件：课次/项目17-答辩PPT/企业风险评估系统-答辩汇报-v2专业版.pptx（19 页）

【问题诊断（已确认，不用你再论证）】
现有 PPT 的最大问题不是排版，是「像 AI 写的」：
1. 每页都是「定义 + ①②③ + 分号排比」；
2. 每页都有结论条（11/19 页），结论应该由人讲出来，不该铺在屏幕上；
3. 小数位过多（0.9877、96.43%、59.6%–61.9%）；
4. 标题连续 6 页同款对仗结构；
5. 全篇只有结论，没有「我一开始以为 X，后来发现 Y」的过程；
6. 抽象词密集（构念、降噪、裁决、闭环、抓手）。

【任务】
产出两样东西：

(1) 一份「逐页改造表」（表格，不要散文），列：
   页号 | 原标题 | 新标题（≤20 字，人话） | 屏幕保留的字（≤30 字） | 讲稿（60–120 字，口语） | 依据（引用哪个文件/数字）
   范围：第 3 页起全部正文页（封面与结束页可不动）。

(2) 一份「新增页清单」：最多 3 页，必须是「过程页」，例如
   「我以为分档写错了 → 拉原始分数一看 40–59 只有 213 家 → 是阈值把分数挤上去了」。
   每页给：标题、屏幕字、讲稿、需要哪张截图（截图在仓库 `课次/项目17-答辩PPT/截图/` 里选，不要新做图）。

【硬约束】
- 数字一律降精度：α 写 0.99、PC1 写 96%、重合率写「约六成」；精确值只出现在讲稿或附录备注里；
- 禁止新增任何未实测的数字；
- 禁止使用：构念、赋能、闭环、抓手、维度、综上所述、值得注意的是；
- 每页屏幕上不超过 30 个字（标题除外）；
- 讲稿必须是口语，允许「我一开始以为」「后来发现」「说实话这个数我算了两遍」这类表达；
- 如果你能直接改 pptx，就输出新文件（命名 `...-v3.pptx`）并说明改了哪几页；如果不能，只输出上述两份表。

【自检（回复前逐条确认，把结果写在最后）】
□ 每页是否只剩一个判断？ □ 屏幕字数是否 ≤30？ □ 有没有一页出现两个以上分号？
□ 是否至少有一页写了「我一开始以为」？ □ 所有数字是否能在 docs/STATISTICS.md 找到？
```

## 三、提示词 C：写实训报告

```text
你要为这个项目写一份课程实训报告。仓库：{仓库地址}

【第一步：必读】
- AGENTS.md
- docs/REPORT-GUIDE.md   ← 报告骨架、可引用数字、摘要模板、不能写的话，全部以它为准
- docs/STATISTICS.md     ← 统计口径与实测值
- docs/TESTING.md        ← 测试用例结构与模块归并
- 课次/项目16-系统测试报告/README.md  ← 已有的测试报告结构与实测数据
- 课次/课程总览.md       ← 17 个课次分别做了什么
- 需要细节时再查：docs/ARCHITECTURE.md、课次/项目NN-*/README.md

【任务】
按 docs/REPORT-GUIDE.md 的骨架，写一份 **10000–14000 字** 的实训报告（中文）。

结构（必须按此顺序，不得增删章）：
封面信息（课程/题目/姓名/学号/班级/指导教师/日期）
摘要 + 关键词（200–300 字）
1 需求分析
2 系统设计
3 系统实现（六模块各一节）
4 数据与模型（含评分模型与统计发现）
5 系统测试
6 部署与运行
7 总结与展望
附录 A 用例索引
附录 B 核心代码与数据字典

每章内部用二级标题，正文用短段落（每段 ≤5 行），关键结论用加粗。

【硬约束（违反即返工）】
1. 所有数字只能来自 docs/STATISTICS.md、docs/REPORT-GUIDE.md 第二节、或课次/项目16 的实测表；**一个新数字都不许编**；
2. 不要写「模型准确率 95%」这类没有依据的指标（本项目没有监督学习模型）；
3. 必须如实写限制：数据只有一期快照、近年评分是模拟值、四维高度共线（α=0.99）、50 并发错误率 18%–22%、AI Key 明文存储；
4. 第 3 章每节用「要解决什么 → 关键代码（10–20 行）→ 页面截图位置 → 遇到的问题与修法」四段式；代码从仓库真实文件里摘；
5. 不要出现：综上所述、值得注意的是、赋能、闭环、抓手、维度（改用「方面/角度」）；
6. 引用图表写「如图 3-2 所示」，并在文末给「图表清单」（图号-说明-来源文件）。

【输出格式】
- 首选：直接生成 .docx（python-docx），正文宋体小四、1.5 倍行距、标题黑体、表格三线表；
- 次选：输出 Markdown，我会自己转 Word。若输出 Markdown，请在文件头写清建议的排版参数。

【自检（写在回复最后）】
□ 全文是否没有出现「准确率」？ □ 每个数字能否在三个来源之一找到？
□ 六条限制是否都写了？ □ 每章是否都有小节？ □ 字数是否在区间内？
```

## 四、如果对方 AI 出错，用这三句话纠偏

| 现象 | 你回它这句 |
| --- | --- |
| 开始编数字（如「准确率 96.2%」） | 「停。把你这次回复里所有数字列一张表，逐个标注来源文件与行号；标不出的删掉。」 |
| 又写成 AI 腔（排比 + 结论条 + 抽象词） | 「把这段改成你会跟同学口头解释的说法，30 秒能说完，不要分号，不要『首先其次』。」 |
| 不肯读仓库、直接给通用建议 | 「先回答三个只有读过代码才知道的问题：`risk_calc.py` 里的两种口径叫什么？`analytics.py` 里 PC1 用什么方法算的？`has_demo` 判断依据是什么？答不上来就别继续。」 |

---

## 五、你要自己把关的三件事

1. **数字对得上**：它交稿后，抽 3 个数字去 `docs/STATISTICS.md` 核；对不上就整段退回；
2. **过程是真的**：PPT 里「我一开始以为…」那种页，必须是真实发生过的（比如分档断崖、等级不同步、缓存 60 秒），不要让它编故事；
3. **限制要说**：报告里那六条限制一条都不能少——评委最容易在这里追问，主动写比被问出来强。

## 六、一次性总提示词（懒人版，把三条合成一条）

```text
读仓库 {仓库地址} 的 AGENTS.md、docs/PPT-REVIEW.md、docs/STATISTICS.md、docs/REPORT-GUIDE.md 后，按顺序做三件事，
每做完一件停下来等我确认，不要一口气做完：

1) 先用 800 字给我评审意见：PPT 最该改的 3 处、报告最容易失分的 2 处、一个「只改 4 页」的最小方案；
2) 我确认后，输出「逐页改造表 + 最多 3 页过程页」（表格，不要散文）；
3) 我再确认后，写 10000–14000 字的实训报告（结构见 docs/REPORT-GUIDE.md）。

三条通用红线：不许编数字、不许用「综上所述/赋能/闭环/抓手/维度」、不许把结论都写成结论条。
所有数字必须能追溯到 docs/STATISTICS.md 或课次/项目16 的实测表。
```
